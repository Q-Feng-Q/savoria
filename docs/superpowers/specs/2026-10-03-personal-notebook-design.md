# 个人生活簿设计

日期：2026-10-03
状态：界面与主要业务规则已由用户确认，待书面规格复核

## 目标与边界

在用户端微信小程序增加独立的「记事」模块，记录单次事项与持续事件，例如纪念日、生理期或日常状态。记录默认私密，归属于登录用户账号，与家庭、商户身份无关。用户可自建事件模板、按日期查询、向指定联系人限时共享，并复制或导出结构化 JSON。

模块按未来可独立部署的边界设计。首期仍使用现有应用的登录、部署和数据库基础设施；记事业务不依赖家庭、订单、商户等领域数据。平台管理员只配置全局查询时段上限，无权通过管理界面读取个人记事正文。

本设计不包含自动生理期预测、医疗建议、统计图表、批量历史模板迁移、文件/录音/定位/公式字段或第三方分析平台集成。生理期只是用户可创建的一种事件，不提供医疗结论。

## 已确认的产品决策

## 信息架构与页面

1. **记事首页**：默认月历。顶部显示私密状态、日历/今天/时间流切换、事件和分类筛选。月历用少量颜色区分连续记录和单日记录；选中日期后显示当天记录摘要。右下角新增记录。今天视图聚焦当天与近期提醒；时间流按发生时间倒序。未登录时沿用现有登录引导，空数据时引导创建首个事件。
2. **事件管理**：查看事件、按用户自定义顺序排列、标记重点关注、筛选分类、归档或删除。重点关注优先展示，但不改变分享权限。用户可创建、查看、编辑和删除自己的事件。归档仅隐藏于默认列表，可取消归档；删除前列出受影响的记录、模板和共享授权并二次确认。确认删除后，事件、记录、模板、授权及其私有附件从业务存储中删除，审计日志仅保留不含正文的动作元数据；首期不提供恢复入口。
3. **事件详情**：显示事件说明、当前模板版本、最近记录、共享状态及入口；提供新增记录、查询历史、编辑事件、编辑模板、共享、复制和导出。查询时间段可选任意历史区间，只限制**单次跨度**，不以「距离今天 36 个月」限制历史数据。
4. **模板编辑器**：创建事件时定义初版模板；之后每次发布变更生成新版本。字段可排序、设必填和选项；保存前预览记录表单并说明历史记录不自动改写。
5. **记录编辑与详情**：记录有标题、发生起止时间、可选备注以及事件模板字段。起止时间支持单日和连续时段；附件字段使用私有图片上传。旧记录按创建时模板展示和编辑；用户如要使用当前模板字段，需显式选择升级该条记录，并保留升级前修订快照及审计记录。
6. **联系人和共享**：家庭成员只作为候选联系人。家庭外用户可通过账号标识或一次性分享码邀请；对方确认后进入记事模块自己的联系人列表。事件所有者逐个联系人设置共享授权，并可查看、修改或撤销。被共享人有「共享给我的」入口。
7. **复制和导出**：事件详情选择起止日期后显示记录数和风险提示；复制到系统剪贴板或生成 JSON 文件。共享用户只有在单独获得导出权限时可执行这两种操作。
8. **平台管理端**：在既有「平台配置」页增加「记事单次查询最长月份」字段。仅平台管理员可修改；管理端不提供记事正文浏览或导出页面。

界面使用项目现有暖纸色、深棕文字、橘色主操作和鼠尾草绿辅助色。底栏保持五项原生导航。日期和记录摘要有清晰的私密标识；敏感值仅在进入有权限的详情后展示。触控目标、安全区、窄屏排版和空/加载/错误状态沿用现有小程序规范。

## 领域模型与隔离

后端业务代码集中于 `com.familykitchen.notebook`，接口集中于 `/api/notebook/**`，数据库表统一以 `notebook_` 开头。小程序页面集中于 `frontend/pages/notebook/`，网络调用集中于 `frontend/services/notebook.js`，必要的无界面状态逻辑放在 `frontend/utils/notebook-*.js`。记事模块只通过登录上下文获取 `userId`；联系人候选和平台配置通过明确的接口读取，不跨领域调用其他模块的 Mapper。现有 `createApiRuntime` 只增加一个 `notebook` 服务门面。

核心实体：

| 实体 | 主要信息与规则 |
| --- | --- |
| Event | `id`、`ownerUserId`、名称、分类、描述、排序值、重点关注、归档状态、创建/更新时间。所有权不含 `familyId`。 |
| TemplateVersion | 所属事件、递增版本号、不可变字段定义、发布时间；历史版本不能原地修改。 |
| Record | 所属事件、所有者、作者、最后编辑者、发生起止时间、标题、备注、模板版本、字段值、乐观锁版本、创建/更新时间及删除状态。 |
| Contact | 以两个用户账号及双方确认状态建立关系；可记录候选来源，但不依赖家庭关系持续存在。 |
| Grant | 事件、授权人与被授权人、记录时间范围、授权起止时间、`canCreate`、`canEdit`、`canExport`、状态。默认三项均为 `false`。 |
| Audit | 操作者、事件/记录、动作、时间与必要的结果摘要；涵盖授权、撤销、查看、编辑、复制和导出。不得把字段正文重复写入日志。 |

字段类型支持单行文本、长文本、数字与单位、日期、时间、日期时间、单选、多选、布尔开关、1～5 评分、图片附件。字段 `key` 由服务端生成且在同一语义下稳定；改显示名不改 `key`，改数据类型须产生新 `key`。删除字段仅从新模板版本移除，旧记录仍按原字段定义显示和导出。模板版本和记录修订保证历史数据能被解释。

图片以私有对象或既有私有文件能力保存，读取时需服务端重新校验记录访问权。导出的 JSON 只包含附件名称、类型等元数据，不提供永久公开 URL 或图片二进制。

## 权限和共享规则

所有读写均由后端依据当前登录用户进行校验，前端隐藏按钮只用于改善交互。本人始终可以管理自己的事件、模板、记录、授权和导出。平台管理员身份、家庭管理员身份或商户身份不自动授予阅读权。

授权需联系人确认后建立；每项授权同时限定一个事件、被授权人、记录发生时间范围和授权有效期。只有两种范围都满足时才能读取。数据范围在创建或更新时不能超过当时全局月份上限；全局上限缩短后，后续读取也按新上限分页或重新选择时段，不删除原记录或原授权。授权可提前撤销，到期或撤销后的新请求立即失效。已经复制或下载到外部的数据无法远程撤回，授权界面和导出前明示这一点。

| 操作 | 默认共享 | `canCreate` | `canEdit` | `canExport` |
| --- | --- | --- | --- | --- |
| 读取授权范围内记录 | 允许 | 允许 | 允许 | 允许 |
| 在授权数据范围内新增记录 | 禁止 | 允许 | 禁止 | 不单独授予 |
| 编辑授权范围内记录 | 禁止 | 禁止 | 允许 | 不单独授予 |
| 复制或导出授权范围内数据 | 禁止 | 禁止 | 禁止 | 允许 |
| 删除记录、改模板/事件、转授权 | 禁止 | 禁止 | 禁止 | 禁止 |

这些权限是独立布尔开关，而非互斥角色；`canEdit` 只允许修改已有记录，新增仍要求 `canCreate`；`canExport` 不包含编辑能力。协作者创建的记录仍由事件所有者持有，同时保留作者。协作编辑使用记录版本号校验，冲突时提示重新载入，不静默覆盖。所有者可删除记录和事件；协作者不得删除。可编辑范围内的记录包括其他协作者所写记录。

共享访问只返回发生起止时间**完整落在授权数据区间内**的记录。跨越授权边界的记录不对被授权人展示、编辑或导出；所有者可扩大共享数据区间后让该记录进入授权范围。新增或修改记录也必须保证整个发生区间位于授权数据区间内。这样无需向被授权人显示授权区间外的日期或字段值。

## 查询、复制和导出契约

记录列表、日历查询、复制和文件导出都要求明确的闭区间 `from` / `to`。本人查询按记录发生区间与请求区间相交返回，月历可展示跨月持续记录；被授权人查询还须满足记录完整落入授权数据区间的规则。查询跨度按**触及的日历月份数**计算：`(to.year - from.year) × 12 + (to.month - from.month) + 1`，不能超过当前平台配置，默认 36 个月。例如 2024-01-01 至 2026-12-31 为 36 个月，2026-01-31 至 2026-02-01 为 2 个月。`from` 不得晚于 `to`；无界列表不返回记录正文。跨大区间使用分页或游标，不在小程序一次渲染全部记录。平台设置读取不到时服务端使用默认 36 个月并记录配置异常；客户端显示服务端返回的有效上限。时区以用户本地日期展示，API 时间使用含时区的 ISO 8601 格式。

复制与文件导出使用同一份服务端生成的数据契约，顶层为 `schemaVersion: "notebook-export/v1"`、导出时间、查询区间、事件信息、所涉及的模板版本定义和按发生时间排序的记录数组。每条记录包含 ID、发生起止时间、模板版本、字段 `key` 与值、作者标识和附件元数据。旧版本字段仍出现在对应模板定义中。导出前再次校验当前权限、授权有效期、数据范围和跨度；超限或撤销返回明确错误，不产生部分导出。复制文本过大时显示大小提示并引导改用 JSON 文件，文件导出采用受控下载而非永久公开链接。复制/导出动作写审计日志。

示例结构：

```json
{
  "schemaVersion": "notebook-export/v1",
  "exportedAt": "2026-10-03T10:30:00+08:00",
  "range": { "from": "2026-01-01", "to": "2026-10-03" },
  "event": { "id": "evt_1", "name": "生理期", "category": "身体记录" },
  "templateVersions": [
    { "version": 3, "fields": [{ "key": "pain", "type": "rating", "label": "疼痛程度" }] }
  ],
  "records": [
    {
      "id": "rec_1",
      "occurredFrom": "2026-10-03T08:00:00+08:00",
      "occurredTo": "2026-10-03T23:59:59+08:00",
      "templateVersion": 3,
      "values": { "pain": 2 },
      "createdBy": "owner"
    }
  ]
}
```

具体端点在实施计划中按现有 `docs/api-spec.md` 的命名和响应约定确定，并在实现时同步更新该 API 文档。至少覆盖事件/模板/记录 CRUD、三视图查询、联系人邀请与确认、授权管理、复制/导出、审计读取和平台月份配置。

## 异常与验收

页面分别处理未登录、空事件、空日期、加载失败、记录冲突、授权过期、权限被撤销、超出月份上限、图片不可用、复制失败和导出失败。被授权人访问失败时不透露事件是否存在。模板提交失败保留草稿；记录编辑有未保存离开提醒。导出失败不会留下可公开访问的临时文件。

验收以以下行为为准：

1. 底栏显示五项；「记事」默认进入日历，原餐篮可从点菜流程进入；三视图切换与事件筛选一致。
2. 新用户可创建事件与自由字段模板，新增跨日或单日记录；修改模板生成新版本，历史数据仍可查看和导出。
3. 所有权随账号而非家庭；家庭外联系人确认后可获限时共享。只读、新增、共同编辑、导出权限按授权独立生效，撤销立即阻断新请求。
4. 事件、记录与授权的增删改查和排序/重点关注均能完成，协作冲突有明确提示和审计记录。
5. 查询、复制、导出受同一全局月份上限约束；默认 36 个月，平台管理员可在 1～36 个月内调整；任意历史区间只要单次跨度合规就能访问。
6. JSON 能完整表达事件、字段版本与记录值；小程序可复制并下载文件；无权限者、过期授权者无法复制或导出。
7. 模块数据、API、页面和文件读取均受记事模块边界保护；家庭/商户/平台角色不能越权读取正文。

前端契约测试验证导航、视图、模板和导出行为；后端测试验证模板版本、权限矩阵、跨家庭所有权、联系人确认、跨度边界、撤销/过期与协作冲突；管理端测试验证月份配置并运行构建。实施前后均不改动已有 Flyway 迁移，只新增前向迁移。
