# 家庭菜单批量启用设计

## 目标

在小程序商户端的家庭菜单配置页补充快速启用能力，解决商户需要逐项启用菜品的问题。支持一键启用全部在售菜品，以及通过复选框选择菜品后批量启用。

## 范围

- 页面：`frontend/pages/merchant/family-menu/index`。
- 沿用现有家庭菜单读取与保存接口，不新增数据库表或迁移。
- 只改变菜品的家庭菜单启用状态，不修改家庭价、排序和商户菜品上架状态。
- 不实现批量停用、跨家庭操作或服务端新增批量接口。

## 页面与交互

页面工具区提供以下操作：

1. “全选当前列表”复选框：选中当前已加载的全部菜品；再次点击取消全选。
2. 每道菜左侧提供自定义复选框。单项选择变化后同步更新已选数量和全选状态。
3. “批量启用（N）”：仅将已选菜品设置为启用。未选择菜品时按钮禁用，并阻止请求。
4. “一键启用全部”：将当前已加载的全部在售菜品设置为启用，不要求提前勾选。

已启用菜品允许被选中；批量启用是幂等操作，不改变其价格和排序。批量操作成功后清空选择并重新读取服务器数据。

## 数据流与一致性

页面继续维护完整的 `menuDraft`。批量操作从当前草稿复制出新草稿，只修改目标条目的 `enabled` 字段，然后通过现有 `saveFamilyMenu(familyId, { items })` 一次提交完整菜单。

保存期间设置统一忙碌状态，禁用一键、批量、全选、单项选择及逐项保存入口，避免并发覆盖。保存成功后重新加载家庭菜单，以服务器结果作为最终状态；保存失败时恢复操作前的草稿和选择状态，并显示失败提示。

## 边界与错误处理

- 菜单为空时隐藏或禁用批量工具，并展示现有空状态。
- 未选择任何菜品时不发送批量启用请求。
- 全部菜品均已启用时，一键启用全部不重复提交，提示“全部菜品已启用”。
- 页面加载、家庭切换或保存后重新加载时清空已选集合，防止选择状态串到另一家庭。
- 复选框和按钮继续使用项目自定义 `view` 控件，不使用微信原生 `button`。

## 测试与验收

新增或扩展前端测试，覆盖：

- 单项选择、取消选择及已选数量。
- 全选当前列表与取消全选。
- 批量启用只修改选中条目，并保留价格和排序。
- 一键启用全部修改全部条目。
- 空选择与全部已启用时不发请求。
- 保存失败时草稿和选择状态回滚。
- 保存成功后重新读取并清空选择。
- WXML 不引入原生 `button`，小屏宽度下工具区可换行且不横向溢出。

最终运行前端完整测试，并针对家庭菜单页面执行契约与响应式测试。
