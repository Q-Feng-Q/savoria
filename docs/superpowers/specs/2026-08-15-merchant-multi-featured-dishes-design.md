# 商户多推荐菜与家庭首页轮播设计

## 背景与目标

当前系统只支持每个家庭保存一道显式首页推荐菜。新方案改为商户级多推荐：商户在菜品管理名片上直接推荐或取消推荐，最多同时推荐 5 道；推荐结果对商户服务中的所有家庭统一生效。推荐菜在家庭首页以轮播展示，并在家庭点菜列表和商户菜品列表置顶。

本设计沿用暖色动物私厨视觉体系，继续禁止使用微信原生 `button`，并保持小屏、横屏和安全区适配。

## 已确认的产品规则

1. 推荐范围为商户全局，对该商户服务中的所有有效家庭统一生效。
2. 最多同时推荐 5 道菜。
3. 推荐菜内部按最近推荐时间倒序排列。
4. 推荐某道菜时，自动为所有服务中的家庭启用该菜。
5. 家庭已有菜单配置只更新 `enabled`，保留家庭价和排序；缺失配置按基础价新增。
6. 取消推荐不自动停用家庭菜单。
7. 下架已推荐菜时自动取消推荐。
8. 推荐菜在家庭点菜页和商户菜品管理列表置顶。

## 数据模型

新增 Flyway V10 迁移，为 `dishes` 增加可空字段：

```sql
featured_at datetime(6) null
```

并增加适合商户推荐查询的联合索引，例如 `(merchant_id, featured_at)`。

- `featured_at IS NULL`：未推荐。
- `featured_at IS NOT NULL`：已推荐。
- 排序使用 `featured_at DESC, id DESC`。微秒精度表达推荐先后，菜品 ID 为同时间戳提供确定性兜底。

现有 V9 `families.featured_dish_id` 暂时保留。V10 对旧数据执行一次确定性回填：按商户聚合仍有效的旧推荐菜，优先选择被更多家庭引用的菜品，同引用数按菜品 ID 降序，每个商户最多回填 5 道。回填使用同一微秒时间戳时仍由菜品 ID 保证顺序；被回填的推荐菜同时按新规则为该商户所有有效家庭补齐或启用菜单项。新业务不再直接读写旧列，后续删除需单独规划兼容迁移。

## 后端架构

### 推荐接口

在商户菜品接口下新增推荐状态更新操作：

```http
PUT /merchant/dishes/{dishId}/featured
Content-Type: application/json

{ "featured": true }
```

取消推荐使用同一路径并传入 `false`。

接口只从实时登录上下文获取 `merchantId`。必须同时满足商户后台权限与非空 `merchantId`，不得接收客户端传入的商户 ID。

### 推荐事务

推荐事务按以下顺序执行：

1. 锁定当前商户记录，以串行化同一商户的推荐数量判断。
2. 使用 `SELECT ... FOR UPDATE` 锁定目标菜品，并在锁内重新校验菜品属于当前商户且状态为 `active`。
3. 若菜品尚未推荐，统计当前有效推荐数；已达 5 道则返回明确业务错误。
4. 更新菜品 `featured_at` 为当前微秒时间。
5. 查询该商户所有有效家庭，并批量补齐或启用家庭菜单项：
   - 已存在：仅设置 `enabled = 1`，不覆盖 `final_price`、`sort_order`。
   - 不存在：新增为启用状态，家庭价使用菜品基础价，排序放在现有菜单尾部。
6. 提交事务。

所有会实际写入菜品状态的路径必须遵守相同锁序：先锁商户，再锁菜品。覆盖专用 `updateDishStatus`、完整 `updateDish`，以及审核开启后 `DishReviewServiceImpl.approve` 的状态落库路径。状态变为 `inactive` 时，必须在同一事务内清空 `featured_at`，避免推荐与下架并发留下脏状态。

重复推荐同一道菜视为幂等操作，不刷新 `featured_at`，避免无意改变排序。

取消推荐同样按“商户锁、菜品锁”的顺序执行，然后清空 `featured_at`。

### 查询与排序

商户菜品列表排序：

```text
featured_at IS NOT NULL DESC,
featured_at DESC,
id DESC,
原有排序
```

家庭点菜列表仅返回该家庭已启用且菜品已上架的记录，并使用同样的推荐优先顺序。

商户菜品列表与家庭点菜列表现有 `DishView` 响应增加：

```json
{
  "featured": true,
  "featuredAt": "2026-08-15T21:30:12.123456"
}
```

`featured` 表示当前菜品是否处于有效商户推荐状态；`featuredAt` 未推荐时为 `null`。商户菜品接口当前返回完整列表，前端必须在应用搜索和状态筛选前从完整响应统计 `featured=true` 的数量，不能只统计当前筛选结果。OpenAPI、Jackson 序列化和兼容测试覆盖新增字段。

家庭首页返回最多 5 道有效推荐菜。有效条件为：

- 菜品属于当前家庭对应商户；
- 菜品已上架；
- 家庭菜单项已启用。

若商户没有有效推荐菜，则按家庭菜单原排序选择第一道有效菜作为单项回退。

### 首页响应兼容

`FamilyHomeResponse` 新增：

```json
{
  "featuredDishes": [
    {
      "dishId": 100,
      "name": "番茄炖牛腩",
      "description": "酸甜浓郁 · 全家都爱",
      "price": 38,
      "imageUrl": "/uploads/..."
    }
  ],
  "featuredDish": { }
}
```

`featuredDish` 在兼容期返回 `featuredDishes[0]`，避免旧版小程序报错。无任何有效菜品时，两者分别为空数组和 `null`。

### V9 旧接口兼容

旧接口 `PUT /merchant/families/{familyId}/menu/featured` 在兼容期保留，但改为新商户级推荐服务的适配入口：先校验 `familyId` 属于当前商户，再将请求中的 `dishId` 设置为商户全局推荐。它不得继续写入 `families.featured_dish_id`，也不得返回成功却不影响新首页。

新版小程序从家庭菜单页移除旧的“设为首页推荐”操作，统一在商户菜品管理页维护推荐。旧接口在接口文档和 OpenAPI 中标记为 deprecated，并以路由测试锁定适配行为；客户端兼容期结束后再单独删除。

## 小程序交互设计

### 商户菜品名片

菜品名片右侧操作区改为两层：

1. 上方：`推荐` / `已推荐` / `推荐已满`。
2. 下方：现有 `上架` / `下架`。

推荐控件位于上下架控件正上方，与确认效果图一致。控件使用自定义 `view`，包含：

- `aria-role="button"`
- 明确的 `aria-label`
- `aria-disabled`、`aria-busy`
- `hover-class`
- 最小高度 88rpx

仅已上架菜品可以推荐。已推荐菜再次点击即取消推荐。达到 5 道时，其他菜显示不可用的“推荐已满”；已推荐菜仍可取消。推荐和上下架共享同一菜品行锁，重复点击只发送一个请求。

推荐成功后静默刷新列表，推荐菜立即移动到顶部，同时保留当前搜索词和筛选条件。失败时保留当前列表，只释放对应行锁并显示后端业务提示。

### 家庭点菜页

推荐菜排在点菜结果前部，内部按最近推荐优先。推荐菜显示轻量“主厨推荐”标签，不改变分类筛选、搜索和加菜行为。

### 家庭首页轮播

使用微信 `swiper` 容器承载推荐卡片，卡片内部仍使用自定义 `view`：

- 多于 1 道时启用约 4 秒自动轮播与循环播放。
- 仅 1 道时关闭自动轮播和循环，避免无意义动画。
- 支持手势滑动和分页圆点。
- 当前卡片完整展示，下一张轻微露出以表达可滑动性。
- 点击卡片进入对应菜品详情。
- 卡片展示真实菜品简介；缺少简介时显示“今日家庭推荐”。

轮播应尊重现有页面安全区、最大内容宽度和紧凑屏规则，不造成水平页面溢出。轮播自身的横向滑动不应影响底部导航。

## 错误与边界处理

- 无商户权限或 `merchantId` 为空：`FORBIDDEN`。
- 菜品不存在或不属于当前商户：`NOT_FOUND`。
- 菜品未上架：业务校验失败。
- 推荐数量已达 5 道：业务校验失败，并返回可直接显示的中文提示。
- 并发推荐：通过锁定商户记录保证最多 5 道，不依赖前端计数。
- 推荐与下架并发：统一锁序并在锁内复核状态，最终不允许 inactive 菜品保留推荐时间。
- 自动启用家庭菜单失败：整个推荐事务回滚。
- 菜品下架、删除或脏数据：所有展示查询继续过滤非 active 菜品。
- 重复推荐或取消：保持幂等，不产生重复家庭菜单项。

## 测试与验证

### 后端

- V10 迁移顺序、字段和索引契约。
- 推荐成功、取消成功和重复请求幂等。
- 第 5 道允许、第 6 道拒绝，并发请求仍不超过 5 道。
- 同一微秒时间戳的推荐菜按菜品 ID 降序稳定排列。
- 跨商户、无商户权限、`merchantId = null`、未上架菜品拒绝。
- 推荐自动启用所有有效家庭菜单。
- 已有家庭价和排序不被覆盖，缺失菜单项正确新增。
- 专用状态更新、完整菜品更新和审核批准三条下架路径都自动清除推荐，并覆盖推荐与下架并发。
- 商户列表、家庭点菜列表推荐置顶且顺序一致。
- 首页返回最多 5 道、按时间倒序、无推荐时单项回退，并维持旧字段兼容。
- `DishView` 的 `featured`、`featuredAt` 序列化和 OpenAPI 契约，以及商户端从完整响应统计推荐数量。
- V9 旧推荐接口适配到商户级推荐；V10 旧数据按引用数、菜品 ID 和最多 5 道规则确定性回填。

### 小程序

- 推荐控件位于上下架控件上方。
- 新版家庭菜单页不再显示旧的分家庭推荐操作。
- 推荐、取消、达到上限、失败解锁和重复点击。
- 推荐后静默刷新并保留搜索和筛选状态。
- 商户列表与点菜列表置顶及推荐标签。
- 首页轮播单项、多项、自动播放、循环、手势和分页状态。
- WXML 表达式、WXSS 编译、自定义按钮禁用契约。
- 320px 紧凑屏、大屏手机、横屏和安全区响应式回归。

### 运行时验证

完整自动化测试通过后，在确认属于本项目的开发后端进程后安全重启，验证 Flyway V10、OpenAPI 新接口、推荐/取消真实链路和家庭首页返回。不得停止或覆盖来源不明的进程。

## 不在本次范围

- 商户手动拖拽推荐排序。
- 推荐排期、权重、分家庭推荐和个性化推荐。
- 删除 V9 `families.featured_dish_id`。
- 修改推荐卡片之外的家庭首页整体视觉结构。
