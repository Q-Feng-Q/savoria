# 家庭厨房单容器部署设计

## 目标

为小规模、单机运行的家庭厨房项目提供一个开箱即用的 Docker 镜像。单个容器同时运行 MySQL、Spring Boot 和 Nginx；HTTPS 由宿主机现有反向代理处理。

## 运行架构

- Nginx 监听容器 `8080`，托管 `admin-web` 构建产物，并代理 `/api/` 和 `/uploads/`。
- 微信小程序源码不在容器中运行，仍由微信平台发布，并通过 HTTPS 域名访问容器 API。
- Spring Boot 监听 `127.0.0.1:8081`，只接受容器内部访问。
- MySQL 监听 `127.0.0.1:3306`，只接受容器内部访问。
- PID 1 使用 `tini`，入口脚本负责三个进程的启动顺序、就绪等待、异常退出和优雅停止。
- Spring Boot 通过 Flyway 初始化和升级数据库，不再要求外部 MySQL。

## 持久化

镜像仅声明一个持久化根目录 `/data`，部署时映射一个命名卷或宿主机目录。目录结构固定为：

- `/data/mysql`：MySQL 数据目录。
- `/data/uploads`：公开上传文件。
- `/data/feedback-private`：意见反馈私有附件。
- `/data/dish-template-assets`：模板菜品私有素材。
- `/data/backups`：容器内备份命令生成的备份文件。
- `/data/config`：容器自动生成的 MySQL 内部 root 凭据。

删除或重建容器不会删除以上数据。日志输出到 Docker 标准输出，不写入持久化目录。

## 初始化与配置

- 首次启动使用 `mysqld --initialize-insecure` 初始化本地 MySQL，仅允许回环访问。
- 入口脚本创建业务数据库和业务账号，并在后续启动时同步业务账号密码。
- JDBC 地址由容器内部自动生成，部署者不再填写数据库地址。
- 必填敏感配置包括数据库业务密码、JWT 密钥和后台管理员初始密码。
- 数据库名和用户名只接受安全字符；密码拒绝空值、开发占位值以及不适合 SQL 初始化的字符。
- 不依赖项目目录中的 `.env`。可以通过 `docker run -e` 传参，也可以显式指定服务器上的 `family-kitchen.env` 文件。

## 资源与安全

- 默认 JVM 最大堆为 `512m`。
- MySQL 默认使用面向小型部署的连接数和 InnoDB 缓冲池设置，可通过环境变量调整。
- MySQL 和 Spring Boot 均不映射宿主机端口。
- 建议宿主机至少提供 2 GB 内存，4 GB 更稳妥。
- 对外只映射 HTTP 端口；生产环境由宿主机反向代理终止 HTTPS。

## 健康与故障处理

- 启动顺序为 MySQL、数据库初始化、Spring Boot、Nginx。
- 健康检查同时验证 MySQL socket 和经 Nginx 代理的公开接口。
- 任一核心进程意外退出，入口脚本停止其余进程并退出容器，由 Docker 的重启策略恢复。
- 收到 `TERM`、`INT` 或 `QUIT` 时，入口脚本转发信号并等待子进程退出。

## 验收标准

1. 一个镜像、一个容器即可运行管理后台、API 和 MySQL。
2. 首次启动能够建立数据库并执行 Flyway 初始化脚本。
3. 重建容器并挂载同一个 `/data` 后，数据库和文件保持不变。
4. 宿主机只需反向代理容器 HTTP 端口即可提供 HTTPS。
5. 部署文档包含构建、启动、健康检查、备份、恢复和升级命令。
